## Emergency containment (operator procedure, not executed automatically)

Do not roll back to the older APIs that allowed anonymous invite writes or bulk ledger overwrite. Do not drop the new tables, restore old grants, remove archives or replay old Storage JSON over committed workspaces.

If a new write path is faulty, temporarily revoke EXECUTE from `authenticated` for the affected `no_app_*` mutator, leave read RPCs available, deploy an explicit maintenance/error response for that path, then release a tested forward fix. Capture the current release receipt and immutable audit records before remediation. Regrant only the original authenticated scope after fixing and verifying the function.

Example targeted containment for workspace writes:

```sql
begin;
revoke execute on function public.no_app_commit(text,bigint,uuid,jsonb) from authenticated;
notify pgrst,'reload schema';
commit;
```

This preserves all business data and archives. It deliberately stops the affected write operation; it is not a destructive schema down-migration.
